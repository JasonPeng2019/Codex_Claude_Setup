# Repository agent instructions

These instructions supplement the user's request and the repository's existing
conventions. More specific instructions closer to a file take precedence.

## Working agreement

- Inspect the relevant code, tests, and repository guidance before editing.
- Make the smallest complete change that solves the requested problem.
- Preserve unrelated user work. Do not clean up or reorganize code outside scope.
- Follow the repository's existing build, test, formatting, and dependency tools.
- Make reasonable low-risk assumptions; state assumptions that materially affect
  behavior, compatibility, safety, persistence, or public interfaces.
- Report exactly what changed, what was checked, and what remains uncertain.
- Do not claim completion while required work or relevant verification remains.

## Use the included skills

- Use `principles` before specifications, architecture, broad edits, or important
  design decisions.
- Use `project-topology` when deciding whether work needs a plan, review,
  delegation, parallel writers, or staged execution.
- Use `bounded-run` for long-running but finite or failure-prone commands,
  servers/watchers, and broad tests/builds. Do not impose timeout bounds on
  open-ended command-line agent sessions.
- Use `verify` after implementation and whenever the user asks to test, lint,
  build, type-check, or verify.
- Use `checkpoint` only when asked to pause, save state, prepare for compaction, or
  hand work to another session.
- Use the focused utility skills when their descriptions match the task.

## Optional research skills

- The default `software` catalog exposes the existing general/software skills.
- Run `python .agent/select-skillset.py research` to add the portable research
  skills to both Codex and Claude discovery catalogs. Run
  `python .agent/select-skillset.py software` to remove only those optional
  research skills again.
- Restart the agent session after changing the catalog. This switch changes
  skill visibility only; it does not change permissions, hooks, verification,
  or the multi-agent launcher.
- Edit optional research skills only under `.agent/skillsets/research/`; the
  visible copies are regenerated by the selector.

## Execution and verification

- Prefer focused checks first, then the owning subsystem's checks. Run the full
  repository gate when requested or justified by broad/high-risk changes.
- Missing tools, skipped checks, and ambiguous commands are not passes.
- Do not install dependencies merely to run a check unless the user authorizes it.
- Do not run full-repository verification automatically when ending a response.
- The Stop gate is completely dormant unless the provider process inherits
  `AGENT_STOP_GATE_ENABLED=1`. If that master switch and
  `.agent/stop-verify.json` are both enabled, the hook runs only the configured
  checks against eligible source files changed since the durable verification
  snapshot; it never substitutes a full-repository gate.
- A timeout means the operation did not complete; it is not proof that the product
  passed or failed.

## Delegation

- One agent is the default for small or tightly coupled work.
- Delegate only independent investigation, review, or implementation with clear
  scope, output, write authority, and completion conditions.
- Keep one writer when implementation areas overlap. The primary agent integrates
  all results and verifies the integrated state.

## Destructive and external actions

- Resolve and inspect exact targets before destructive filesystem or Git actions.
- Never recursively delete a filesystem root, home directory, or repository root.
- Do not discard user changes, mutate `.git` internals, commit, push, publish, or
  contact external people unless the user has clearly authorized that action.
- Catch verified target mistakes, but do not obstruct an intentional and correctly
  targeted risky operation the user explicitly authorized.
